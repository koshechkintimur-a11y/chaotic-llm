# Experiment 08 — Error Controller

## Hypothesis

Контроллер ошибки наблюдает X_t, оценивает E_t, и останавливает/корректирует траекторию. Снижает ли это число итераций и стоимость (уровень 5)?

## Setup

ChaoticDeepSup: 8 блоков с readout на каждом блоке (deep supervision, суммарный loss). На inference — ранний выход, когда argmax не меняется 2 блока подряд («ошибка перестала уменьшаться»).

## Results

| Метрика | Значение |
|---|---|
| acc_fixed_depth8 | 0.193 |
| acc_early_exit | 0.193 |
| mean_exit_depth | 8.0 |
| compute_saved_frac | **0.0** |

## Interpretation

- **Наивный критерий раннего выхода не сработал**: предсказания менялись до самого конца (средняя глубина выхода = 8 из 8). Экономии compute — ноль.
- Причина: модель не достигала уверенности (точность ~0.2), argmax «блуждал».
- Deep supervision (суммарный loss по всем блокам) не улучшил точность относительно обычного обучения (0.193 vs 0.205 в exp_07).

## Conclusion

**Опровергнуто (в текущей формулировке)**: наивный error controller не экономит compute. Нужен критерий уверенности (например, энтропия распределения ниже порога) и модель, которая вообще достигает уверенных предсказаний.
