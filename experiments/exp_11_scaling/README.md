# Experiment 11 — Scaling Laws (N = 9..256)

## Hypothesis

Может ли Proposed демонстрировать рост O(N) или O(N log N) вместо O(N²) при сопоставимой точности? (§19 — запрещено заявлять дешевизну «по формуле»; считаем ВСЕ операции.)

## Setup

Задача: N токенов с уникальными ключами, query в конце, retrieval по ключу (V=32). Модели: Chaotic (MLP readout), ChaoticAttnReadout, FullAttn. d=32 фиксировано, 300–400 эпох. FLOPs — аналитический учёт всех операций.

## Results

| N | Chaotic acc | Chaotic+AttnRead acc | FullAttn acc | FLOPs C | FLOPs A | FLOPs F |
|---|---|---|---|---|---|---|
| 9 | 0.147 | 0.158 | 0.897 | 2.0e3 | 2.0e4 | 1.8e5 |
| 16 | 0.081 | 0.321 | 0.869 | 3.8e3 | 3.7e4 | 3.4e5 |
| 25 | 0.071 | 0.075 | 0.054 | 6.8e3 | 5.8e4 | 5.9e5 |
| 64 | 0.033 | 0.033 | 0.033 | 2.1e4 | 1.5e5 | 2.2e6 |
| 121 | 0.030 | 0.027 | 0.033 | 4.3e4 | 2.9e5 | 5.9e6 |
| 256 | 0.029 | 0.031 | 0.031 | 1.0e5 | 6.3e5 | 2.2e7 |

## Interpretation

1. **Сложность**: FLOPs растут как O(N log N) (Chaotic: 2e3 → 1e5 при N: 9 → 256, множитель ~52×) против O(N²) (FullAttn: 1.8e5 → 2.2e7, множитель ~122×). Разрыв: 90× → 212×.
2. **Точность**: при N ≥ 25 ВСЕ модели падают к шансу (0.03). Причина — фиксированная ёмкость d=32 и бюджет эпох: задача (N уникальных ключей) растёт, модель не успевает. Это предел toy-масштаба, а не свойство архитектур.
3. **Честный вывод**: на toy-масштабе кривую «Accuracy vs N при равной ёмкости» построить не удалось — все модели упираются в потолок бюджета. Сравнение точности возможно только при N ≤ 16 (там FullAttn ≈ 0.87–0.90, Chaotic+AttnRead ≈ 0.16–0.32 — attention лучше на малых N).

## Conclusion

**Не подтверждено (в текущем масштабе)**: преимущество точности при росте N не продемонстрировано — toy-задача насыщается быстрее, чем модели учатся. Сложностное преимущество O(N log N) vs O(N²) подтверждено учётом FLOPs, но «то же качество при меньшем compute» на N>16 не показано.
