# Ответ на ревью: NB-1a СДЕЛАН, NoteBook — масштабируемая память, не только кэш

## Коротко

Коллега был прав в главном (NB — не обучаемый prior, TrustScorer перспективнее),
но два его тезиса опровергнуты данными: (1) «NB-1a не сделан» — сделан; (2)
«работает только в ходе прохода (recency)» — нет, статическая память работает.

## Результаты NB-1a (статический справочник, построенный на train, применён на test БЕЗ обновлений)

| Корпус | nb0 (морен β=0.3) | nb1 online (recency) | **nb1 STATIC (NB-1a)** | nb2 static |
|---|---|---|---|---|
| corpus5m | 8.06 | 6.35 | **6.15** (−24%) | **5.43** (−33%) |
| Stack 20MB | 24.68 | 23.73 (−4%) | **22.65 (−8.2%)** | 22.97 |

Записи справочника: ~177K (Stack) / ~186K (corpus5m) = ~2-3MB.

## Что это опровергает

**Тезис 1 «NB-1a не сделан / работает только в ходе прохода» — ОПРОВЕРГНУТ.**
Справочник, собранный один раз на train, даёт −8.2% на Stack и −24% на corpus5m
на НЕВИДАННОМ тесте, без какого-либо обновления в тесте. Это статическая память,
не recency-кэш. Она строится заранее и применяется как есть.

**Тезис 2 «это дополнение, не масштабируемый prior» — частично.**
Масштабируемая память да: растёт с корпусом (больше train → больше записей → шире
покрытие). Обучаемый prior — нет: 0 параметров, никакого градиента. NB — это
**масштабируемая табличная память**, отдельный класс от TrustScorer (обобщение).

## Почему static > online (честно)

Online тратит первые ~500 позиций теста на разогрев (записи ещё пусты). Static
использует полный справочник с первой позиции. Плюс static не зависит от порядка
прохода — детерминирован.

## Сравнение (уточнённое)

| Метрика | TrustScorer | NoteBook (static) |
|---|---|---|
| corpus5m | −33% | −33% (nb2) / −24% (nb1) |
| Stack | провал (0.70×) | **−8.2%** |
| Механизм | Обобщение признаков | Табличная память |
| Параметры | 6 весов | 0 |
| Масштабирование | Обучаемый | Табличный (растёт с корпусом) |
| На LLM | top-1 77% (проверено) | top-1 78.5% (проверено) |

Оба дали топ-1 77-78.5% на DeepSeek-Coder (пилот n=200).

## Вывод

NoteBook — не «только recency-кэш», а **статическая табличная память**, которая
строится заранее и масштабируется с корпусом. Она решает ту часть проблемы, где
TrustScorer провалился (разнообразный код). Оба механизма работают и дополняют
друг друга: TrustScorer обобщает, NoteBook запоминает.

**Следующий шаг (согласен с коллегой): интеграция.** TrustScorer + NoteBook в одном
конвейере: `morin → NoteBook(память) → TrustScorer(признаки) → β`. Ожидание:
суммарный эффект ≈ −33% (TrustScorer на повторах) + −8% (NB на разнообразии).
