# REPORT — Интеграция morin + NoteBook + TrustScorer

**Дата:** 2026-08-30 | **Протокол:** CPU, код, BPE-512, prior order-8, сглаженная trigram-модель

## Архитектура интеграции

```
morin prior (n-граммная таблица)
   │
   ├── NoteBook (статическая память: «prior был прав здесь?»)
   │        trust = smoothed right/(right+wrong)  → признак #7
   │
   └── TrustScorer (логистический head, 7 признаков)
            [match_len, log1p(tot), p_top, n_cand, ctx_len, entropy, NOTEBOOK_TRUST]
            β = σ(w·features)  → обучен на val
```

Head сам учится, как взвесить статическую память и признаки.

## Результаты (test, 10K сэмплов)

### corpus5m (повторяющийся код)

| Конфиг | PPL | vs nb0 |
|---|---|---|
| nb0 (морен β=0.3) | 7.99 | baseline |
| nb1 (справочник) | 6.08 | −24% |
| **T3c (head только)** | **5.68** | **−29%** |
| INT (оба) | 5.80 | −27% |

### Stack 20MB (разнообразный код)

| Конфиг | PPL | vs nb0 |
|---|---|---|
| nb0 (морен β=0.3) | 25.27 | baseline |
| **nb1 (справочник)** | **23.21** | **−8.2%** |
| T3c (head только) | 23.32 | −7.7% |
| INT (оба) | 23.27 | −7.9% |

## Ключевой вывод: механизмы КОНКУРИРУЮТ, не складываются

Гипотеза «−33% + −8% = −40%» НЕ подтвердилась. INT ≈ лучшему из компонентов:

- **corpus5m:** T3c (5.68) > INT (5.80). Вес справочника в head = **−0.34** —
  на повторяющемся коде статические признаки уже сильны, справочник добавляет
  шум, head его приглушает.
- **Stack:** nb1 (23.21) ≈ INT (23.27). Вес справочника +0.04 — head почти
  игнорирует признаки, память доминирует.

**Почему:** признаки head (match_len, p_top, entropy) и вердикты справочника
кодируют ОДНУ и ту же информацию — надёжность prior в данном контексте. Они
избыточны, а не ортогональны. Логистический head это видит и выбирает лучший
сигнал.

## Что это значит

1. **Оба механизма полезны, но не складываются.** Лучшая конфигурация — та,
   что соответствует данным: head на повторяющемся коде, справочник на
   разнообразном.
2. **Автоматический выбор:** head САМ выбрал нужный вес (отрицательный на
   corpus5m, ~0 на Stack) — то есть head можно использовать как универсальный
   селектор «что сейчас важнее». INT на обоих корпусах не хуже лучшего
   компонента (5.80 vs 5.68, 23.27 vs 23.21 — в пределах шума).
3. **Для практики:** простой морен (β=0.3) + справочник на разнообразном коде,
   + head на повторяющемся — либо интегрированный head, который сам выбирает.

## Честные оговорки

- n=10K, один сплит (seed 42) — шум ±0.1-0.2 PPL.
- На LLM (n=200, пилот) отдельные механизмы дали top-1 77-78.5%; интеграция
  на LLM не тестировалась.
- «Конкуренция» измерена на логистическом head; MLP мог бы найти нелинейную
  комбинацию, но это уже следующий вопрос.

## Итог

Интеграция честно проверена: **морен + память + head = не сумма, а выбор.**
Это тоже результат: механизмы избыточны, head это распознаёт. Практическая
рекомендация — head как универсальный роутер, либо выбор по типу данных.
