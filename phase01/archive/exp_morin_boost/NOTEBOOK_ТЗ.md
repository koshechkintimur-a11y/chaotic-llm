# ТЗ: NOTEBOOK PRIOR — «справочник заметок» поверх morin (идея архитектора)

## Проблема (измеренная)

TrustScorer (статический head, β=σ(w·f)) работает на повторяющемся корпусе
(corpus5m: −33%) и ПРОВАЛИВАЕТСЯ на разнообразном (Stack: 0.70× vs morin).
Причина: head требует ОБОБЩЕНИЯ (одна формула для всего кода), а на чужом
коде общего правила нет.

## Гипотеза архитектора

Вместо обобщения — ЗАПОМИНАНИЕ. Регулятор ведёт СПРАВОЧНИК заметок:

```
{контекст-ключ → {шпаргалка права: N, ошиблась: M}}
```

- ЗАПИСЬ: каждый шаг eval/декодинга даёт ground truth (реальный next token
  известен) → обновляем вердикт шпаргалки для текущего контекста.
- ЧТЕНИЕ: для нового контекста — O(1) хеш-поиск → «в похожих контекстах
  шпаргалка права в N/(N+M) случаев» → признак для β.
- ПАРАЛЛЕЛЬНО: lookup независим, не блокирует модель.
- ПАМЯТЬ: ~16 байт/запись; LRU-ограничение; рост O(N) — приемлемо.

## Эксперименты (CPU)

| ID | Что |
|---|---|
| NB-0 | Baseline: morin (β=0.3), как есть |
| NB-1 | morin + справочник: β = f(вердикты заметок), без статического head |
| NB-2 | morin + справочник + статический head (гибрид всех признаков) |

Корпуса: corpus5m (повторяющийся — где head работал) и Stack (разнообразный —
где head провалился). Это решающая пара: если справочник работает на Stack,
гипотеза подтверждена.

## Метрики

- PPL на test (honest split, как раньше)
- top-1 accuracy
- покрытие справочника (доля контекстов с заметкой)
- размер справочника (память)
- отложенная запись vs немедленная (обновление заметок в test = утечка? НЕТ:
  заметки копятся ПО МЕРЕ прохода и предсказывают СЛЕДУЮЩИЙ токен — это
  легальный recency-сигнал, как Cache LM. Но помечаем честно!)

## Предрегистрированные вердикты

- **V1:** NB-1 бьёт morin на Stack (там, где статический head = 0.70×)
  → гипотеза архитектора ПОДТВЕРЖДЕНА: запоминание > обобщение на
  разнообразном коде.
- **V2:** NB-2 бьёт NB-1 → гибрид (заметки + признаки) лучше.
- **V3:** NB-1 не бьёт morin ни на Stack, ни на corpus5m → справочник не
  несёт сигнала сверх morin, закрыть с честным отрицательным результатом.

## Stop-rule

V3 (полный провал) → закрыть линию NoteBook, вернуться к morin (fixed β)
как к рабочему базису. V1 без V2 → справочник работает, статический head
не нужен. V1+V2 → полная архитектура «morin + справочник + head».
