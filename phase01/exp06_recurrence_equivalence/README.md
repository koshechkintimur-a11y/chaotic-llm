# Experiment 06 — Recurrence, Equivalence, C_total

## Hypothesis

Даёт ли «одна система, много маршрутов» преимущество? Не является ли хаотическая архитектура просто более сложным lookup?

## Results

### A. Одна карта, много задач
| N | орбит (выборка 4000) | нижняя граница N²/T |
|---|---|---|
| 64 | 123 | 85 |
| 128 | 245 | 170 |
| 256 | 487 | 341 |

Каждая орбита — ЛИНЕЙНАЯ периодическая функция (Aᵗ·x₀). N независимых блоков выражают N произвольных функций. Экономия параметров одной карты = вес-шеринг RNN (стандартное свойство), покупающая лишь линейные периодические маршруты.

### B. Стоимость маршрутизации (N=128)
| Метод | Индекс | Инференс |
|---|---|---|
| Chaotic router | O(N²) (таблицы орбит) | O(длины орбиты) ~ 82–107 шагов + ограничение досягаемости (0.45% для точечной цели) |
| Hash table | O(K) | O(1) |
| Trie | O(сумма длин ключей) | O(длина ключа) |
| MoE router | O(K) параметров | O(K) softmax |

### C. C_total
C_total = construction + training + index + inference + correction.
- Хаотический роутер: должен обучить ТОТ ЖЕ encoder (context→x₀), что и любой роутер, ЗАТЕМ добавляет индекс O(N²) и скан O(орбиты), и ограничен досягаемостью.
- Это строго более дорогой hash: та же training, +index, +scan, −reachability.

## Conclusion

**Эквивалентность подтверждена**: адресная итерация = замкнутая линейная алгебра (матричная степень); маршрутизация = lookup с дополнительными затратами; управляемая динамика = RNN/MoE. Скрытый перенос стоимости (индекс/тренировка) — именно тот, о котором предупреждает ТЗ §11.
