# EXP Memory Selector — «Память как селектор» (fail-safe MEM)

## ТЗ
Память живёт ПОСЛЕ микшера: `Tokens → Bidirectional Mixer → MEMORY (селектор) → Output`.
Это селектор контента на уровне **предсказания**, не маршрутов (Око закрыто как retrieval-модуль).
Exp09: β-prior (order-3) дал +58% vs +12.5% от Ока. Улучшенная память должна дать ещё больше.

## Инварианты (М1-М4)
- **М1** микшер не меняется (BidirectionalMixer, BLOCKS=4, exp52)
- **М2** память — lookup, строится на train, используется на test (без градиентов)
- **М3** O(1) lookup, O(N) build, <100MB
- **М4** контроли: MEM-R (random), MEM-NoMixer (без микшера)

`mixer_only` = PPL нейро-микшера без памяти. `gated` = PPL после смеси с памятью (adaptive-β).
`q_miss` = доля не найденных паттернов; `t_miss` = найден, но target нет; `cov` = доля вклада памяти.

## Вердикты по ТЗ

**Q1 (улучшенная память > order-3?):**
- MEM-A (order-8): ❌ **ХУЖЕ** (35.5 vs 10.5, в 3.4×). Слишком разрежен (q_miss=0.816).
- MEM-B (content-addr): ❌ **ХУЖЕ** (30.0 vs 10.5, в 2.9×). Разрежен (q_miss=0.757).
- MEM-C (hybrid): ✅ чуть лучше (9.98 vs 10.46, +4.7%), но в пределах шума. Гибрид ≈ order-3 (content-addr часть не срабатывает).

**Первичный критерий ТЗ:** MEM-B < MEM-0 на >10% — **НЕ ВЫПОЛНЕН** (29.97 > 10.46).
MEM-A/B не прошли. MEM-C дал лишь +4.7% (не >10%).

**Q2 (решает ли шум-тест?):** ждём noise_retrieval (MEM-B vs MEM-0).

**Q3 (стоимость):** MEM-B = 9MB / 602K записей (М3 соблюдён: <100MB). MEM-C = 10MB.

**Q4 (нужен ли микшер?):** ждём MEM-NoMixer.

**Частичный успех:** MEM-C +4.7% — слабый. По стоп-правилу ТЗ, если MEM-A/B/C не дали >10% и
нет clear partial-success → **вопрос памяти закрыт** как основной селектор. Order-3 β-prior
(из exp09) остаётся лучшим — расширение порядка НЕ помогает на vocab 512 (разреженность).

## Анализ паттернов (analyze_memory.py)
MEM-B хранит 197K паттернов (L=8..16, убывает 28K→17K). Топ-20: тривиальные повторы
(`378→378`, p=0.9+) И осмысленные детерминированные n-граммы (`[133,14,14,134,37,40,43,36]→25`, p=1.0).
Проблема: разреженность (q_miss=0.76) убивает coverage.

## Вывод
Расширение порядка памяти (MEM-A/B) НЕ улучшает order-3 на vocab 512: пространство 512⁸
слишком огромно, почти все контексты уникальны → память не находит совпадений. Гибрид (MEM-C)
сводится к order-3. **Архитектурный результат: order-3 β-prior (exp09) — оптимален;
улучшение через память Higher-order не работает на дискретном коде.**
