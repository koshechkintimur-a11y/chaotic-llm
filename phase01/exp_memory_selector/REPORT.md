## Ответы на 5 вопросов ТЗ

### Q1: Даёт ли улучшенная память преимущество над order-3?
**НЕТ (для higher-order).** Order-3 β-prior (MEM-0, gated=10.46) — лучший.
- MEM-A (order-8): **35.5** — в 3.4× ХУЖЕ (разреженность: q_miss=0.82)
- MEM-B (content-addr): **30.0** — в 2.9× ХУЖЕ (q_miss=0.76)
- MEM-C (hybrid): **9.98** — лишь +4.7% к MEM-0 (в пределах шума; гибрид сводится к order-3)

**Вывод:** расширение порядка НЕ улучшает order-3 на vocab 512. Пространство 512⁸ слишком огромно → почти все контексты уникальны → память не находит совпадений.

### Q2: Решает ли улучшенная память проблему шум-теста?
**НЕТ.** noise_retrieval (KEY в шуме, W=64..512, noise=95-99.5%):
- MEM-0 (order-3): acc1=0.0–0.4, acc10=0.4–0.67 (работает частично, когда последний токен перед KEY сохранён)
- MEM-B (content-addr): **acc=0.000 для ВСЕХ W и noise** (n=0 — паттерны длины 16 всегда уникальны в шуме)

**Вывод:** content-addressable память НЕ может найти KEY в шуме. Order-3 хотя бы иногда справляется (локальность).

### Q3: Реальная стоимость улучшенной памяти?
- MEM-B: **9.0MB / 602K записей** (М3 соблюдён: <100MB для 1M токенов)
- MEM-C: 10.1MB / 653K записей
- Все памяти: O(1) lookup, O(N) build, 0 параметров (lookup, не градиенты) ✅
- **Цена растёт**, но выигрыша нет → higher-order память неэффективна.

### Q4: Нужен ли микшер вообще?
**ДА, критически.** MEM-NoMixer (только память order-3) = PPL 40.9.
- Микшер один: 62.1
- Память order-3 одна: 40.9
- Микшер + память: **10.5**

Микшер и память **комплементарны**: микшер даёт генерализацию (дальний контекст через хаос), память — точные n-граммы. Вместе → 10.5 (в 4× лучше памяти alone, в 6× лучше микшера alone).

### Q5: Самостоятельное архитектурное направление?
**ЧАСТИЧНО.** «Микшер + умная память» конкурентоспособно (10.5 PPL при O(W·d) сложности vs O(W²·d) у attention).
НО: «умная память» = order-3 β-prior (exp09), НЕ higher-order (MEM-A/B). Расширение порядка не даёт архитектурного скачка.

## Вердикт по стоп-правилу ТЗ

**Гипотеза памяти (MEM-A/B/C > MEM-0 на >10%): НЕ ПОДТВЕРЖДЕНА.**
- MEM-A, MEM-B: провал (разреженность)
- MEM-C: +4.7% (не >10%, не clear partial-success)
- noise_retrieval: MEM-B = 0 (не решает шум-тест)

**По стоп-правилу ТЗ:** «если MEM-A, MEM-B, MEM-C все не прошли и не дали частичного успеха → вопрос памяти закрыт».

**Закрыто:** higher-order/content-addressable память как селектор НЕ улучшает order-3 β-prior на дискретном коде (vocab 512).

**Остаётся оптимальным:** order-3 β-prior (exp09) + BidirectionalMixer (exp52). Это архитектурный базис ChaoticLLM.

MEM-B: 197K паттернов (L=8..16, убывает 28K→17K). Топ-20:

Проблема: разреженность (q_miss=0.76) убивает coverage. Память хранит реальные паттерны, но находит их слишком редко.
