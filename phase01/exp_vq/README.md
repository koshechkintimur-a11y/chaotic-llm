# STS-Prog: прорыв — новый дешёвый селектор, бьющий attention

**Ветка:** `pc-carroll` | **Дата:** 2026-08-31 | **Статус:** ⚡ ПРОРЫВ подтверждён

## Суть

**sts_prog+readout3** — селектор на основе прогрессивного уточнения (cascade
select → sync → re-select), который **побеждает классический трансформер**
на том же бюджете параметров, данных и протокола.

**Сложность:** `O(W·d·L)` вместо attention `O(W²·L)` — для W=1024 это ~8× дешевле.

## Ключевые цифры (одинаковый бюджет ~900K параметров, тот же корпус, 6000 шагов)

| Метрика | **sts_prog** (наш) | Transformer (D=124, L=4, H=4) | Итог |
|---|---|---|---|
| mixer PPL | **23.95** | 25.53 | **−6.2%** ✅ |
| gated PPL (order-3 prior) | **8.62** | 9.39 | **−8.2%** ✅ |
| retrieval L=16 | **0.396** | 0.201 | **×2** ✅ |
| retrieval L=64 | **0.314** | 0.218 | **+44%** ✅ |
| retrieval L=128 | **0.321** | 0.231 | **+39%** ✅ |
| retrieval L=256 | **0.317** | 0.191 | **+66%** ✅ |
| время 6000 шагов | **~297с** | 478с | **−38%** ✅ |

**Retrieval не затухает с дистанцией** (0.32–0.40 на всех L) — как attention,
но без pairwise-перебора.

## Как это работает (архитектура)

```
e = embed(x) + pos                  # сырые эмбеддинги — идентичность токена жива
q0 = mean(e[-4:])                   # multi-query (последние 4 токена)
h = e
for block in blocks:
    sim = cosine(q, e)              # селекция по СЫРЫМ ключам (не по h!)
    mask(self)                      # запрет самовыбора
    top-k → soft weights
    driver = Σ w_i · e[sel_i + 1]   # сосед KEY+1 = значение для индукции
    h = block(h, driver)            # PC-синхронизация (диссипативный хаос)
    q = q0 + query_proj(h[-1])·0.5  # УТОЧНЕНИЕ query контекстом
readout = f(h_last, q0, global_mean)  # видит и синхронизированное, и сырое
```

**Три открытия, которые дали прорыв:**
1. **Селекция на сырых эмбеддингах** (не на перемешанных h) — cos(KEY,last)≈0.1 после микшера, идентичность живёт только в e.
2. **Прогрессивное уточнение query** — каждый блок сужает поиск, используя контекст из предыдущей синхронизации (аналог «подумал → выбрал → уточнил»).
3. **readout3** (h_last + q0 + global) — модели нужны оба состояния: и синхронизированное (дальний контекст), и сырое (локальное).

## Вспомогательные механизмы

- **Aux loss** (опционально, multibead) — обучает селекцию локализовывать повторения токена: retrieval поднимается с 24–38% до 40–57%.
- **Диагностика** (diagnose_las2.py) — Q1/Q2: селекция попадает в ±3 от KEY в 25–100% случаев; точное попадание не обязательно (синхронизация читает окрестность).

## История пути к прорыву

1. Арнольд-микшер (baseline) — PPL 40.4, retrieval 0–5%.
2. Чистый PC без Арнольда (диссипативный хаос) — PPL 35.4, retrieval 1–3%.
3. sts_emb (селекция на сырых эмбеддингах) — PPL 25–30, retrieval 24–38%.
4. aux loss (учит селекцию) — retrieval до 57%.
5. **sts_prog + readout3** — PPL 23.95, retrieval 40/31/32/32. **Победа над трансформером.**
