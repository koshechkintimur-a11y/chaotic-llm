## Вердикты (П5, пороги предрегистрированы, не менялись)

### Q1: Бьёт ли DP базлайн C0 при равной ёмкости (vs C-cap)?
**НЕТ.** DP (42.97) ≈ C-cap (41.26, ±4%). Prior-распространение даёт НОЛЬ над
ёмкостью. Всё улучшение vs C1 (62.1) объясняется большим числом параметров.

### Q2: Сохраняет ли DP связи на L≥256 (кривая accuracy(L))?
**НЕТ.** accuracy = 0 на всех дистанциях (16/64/256/1024) ДАЖЕ БЕЗ шума
(проверено retrieval_clean.py, шум не виноват). Хаос перемешивает, а не
переносит: идентичность токена теряется в перестановках.

### Q3: Несёт ли propagation сигнал (DP vs DP-noprop)?
**ВРЕДИТ.** DP (42.97) ХУЖЕ DP-noprop (36.34) на −6.6 PPL. Статический
prior-embedding помогает (+12% над ёмкостью: 36.3 vs 41.3), но его
распространение через те же перестановки убивает преимущество.

### Q4: Обучаемый prior или структура (DP vs DP-rand)?
**Обучаемость даёт немного, но недостаточно.** DP (42.97) < DP-rand (46.25),
−3.3 PPL от обучения prior. Но оба ≫ порога 9.94 — вердикт не меняется.

### Q5: Динамический prior = архитектура / retrieval / закрыто?
**ЗАКРЫТО (отрицательный результат).** Три независимых теста сходятся:
1. PPL-контроль ёмкости: DP ≈ C-cap → эффект от ёмкости
2. Контроль распространения: propagation ВРЕДИТ
3. Ретривал: связи не сохраняются ни на какой дистанции

**Стоп-правило сработало:** первичный критерий не пройден, частичного успеха
нет → направление «динамический prior» закрыто навсегда. PM/SP не запускались
(по ТЗ: «если DP дал сигнал» — сигнала нет).

## Почему гипотеза не сработала (механизм)

1. **Хаос перемешивает, а не переносит.** Arnold-перестановки + coupling
   эффективно перемешивают информацию внутри окна, но не сохраняют
   идентичность конкретного токена на дистанции.
2. **Readout видит глобальный пул** — среднее по окну размывает локальные
   сигналы prior.
3. **Ёмкость объясняет всё улучшение** — C-cap (41.3) ≈ DP (42.97).

## Значение для проекта

1. Морен-таблица (order-3, C0=10.46) остаётся оптимальным prior — никакая
   обучаемая форма (DP/DP-noprop/DP-rand) не приближается к ней (36-46).
2. Архитектура ChaoticLLM: «Mixer + морен order-3» — подтверждённый оптимум.
3. Направление «обучаемый динамический prior» закрыто с честным
   отрицательным результатом — сэкономлены недели на PM/SP/эскалации.
