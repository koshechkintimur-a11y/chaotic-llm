# Experiment 19 — Chaotic Top-K Readout (Step 7)

## Hypothesis (ключевая для архитектуры)

Chaotic dynamics generates a cheap structured proposal space for selective
computation. Если хаотический mixer организует пространство, то дешёвый
линейный селектор должен находить K релевантных токенов, и attention
применяется только по ним: O(W log W) + O(K²·d) вместо O(W²·d).

## Setup

- BPE-512, 990,811 train / 1,169,238 test, окно 256.
- Hierarchical chaotic mixer (1 проход) + differentiable top-K + attention по K.
- V1: linear selector → top-16 → attention.
- V2: linear → top-64 → content-refine (q·k) → top-16 → attention.
- V3: тройной каскад 64 → 16 → 4 → attention.
- Straight-through top-K (маска бинарная в forward, softmax-градиент в backward).
- 6000 шагов, batch 64, lr 1e-3, β-prior 0.3.

## Results (20,000 тестовых позиций)

| Модель | PPL | PPL+β | top-1+β | Параметры | Attention cost |
|---|---|---|---|---|---|
| V1: top-16 | 33.07 | 13.95 | 40.8% | 103.6K | O(16²·d) |
| V2: каскад 64→16 | 34.81 | 14.29 | 39.7% | 111.9K | O(16²·d) |
| V3: каскад 64→16→4 | 35.03 | 14.21 | 40.2% | 120.2K | O(4²·d) |
| **v0.3 local readout** | **32.83** | **13.79** | 40.7% | 90.8K | 0 |
| v0.2 full attn readout | 32.47 | 13.74 | 40.6% | 99.3K | O(W·d) |

## Interpretation

1. **Top-K attention не превосходит локальный readout** (33.07 vs 32.83 PPL
   модели; 13.95 vs 13.79 с β). Больше стадий каскада — хуже (V3 = 35.03).
2. **Гипотеза НЕ подтверждена в этой реализации.** Селектор не находит
   информативные токены: attention по выбранным K ≈ среднее по K ≈ локальный
   readout (который и так видит глобальный mean).
3. **Две причины**:
   a) **Дискретный top-K не имеет градиента выбора.** Straight-through обучает
      только веса внутри выбранных K, но не сам выбор — селектор застревает
      на ~случайных K.
   b) **Задача не требует селекции**: next-token на коде локальна, β-приор
      доминирует. Широковещательность миксера делает top-K избыточным —
      каждый токен уже содержит сводку всего контекста.
4. Дополнительные параметры селекторов (103-120K vs 90K) не окупаются.

## Conclusion

**Опровергнуто (в текущей реализации)**: «хаос организует пространство →
дешёвый селектор находит нужные K» не подтверждается на next-token задаче.
Нужны: (1) обучаемый выбор (Gumbel-top-K / дистилляция с full-attention
учителя), (2) задача, где контентная селекция реально нужна (retrieval,
а не next-token).
