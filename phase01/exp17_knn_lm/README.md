# Experiment 17 — kNN-LM vs Beta-Prior at Equal Memory (Step 5d)

## Hypothesis (честный инженерный вопрос из morin-filter)

Агрегированный n-граммовый приор (β-prior) лучше kNN-LM retrieval при равном
бюджете памяти?

## Setup

- База: L=1 HierChaoticLM + attention readout (exp14, 6000 шагов).
- Датастор: 990,554 записей (скрытые состояния всех обучающих позиций,
  ключ = 8-мерная случайная проекция, k=16 соседей, λ=0.3).
- Память таблицы β-приора: 28,176 контекстов + 130,856 ассоциаций ≈ **1.80 MB**.
- kNN с равной памятью: K = 49,880 записей (36 Б/запись) = 1.80 MB.
- kNN большой (эталон): K = 990,554 (35.7 MB, без ограничения).

## Results (20,000 тестовых позиций)

| Селектор | PPL | top-1 | Память |
|---|---|---|---|
| Модель alone | 32.47 | 23.3% | — |
| **β-prior** (агрегированная таблица) | **13.74** | **40.6%** | **1.80 MB** |
| kNN равной памяти (K=49,880) | 25.28 | 28.0% | 1.80 MB |
| kNN большой (K=990,554) | 14.68 | 39.6% | 35.7 MB |

## Interpretation

1. **При равной памяти β-приор вдвое лучше kNN**: 13.74 vs 25.28 PPL (1.84×),
   top-1 40.6% vs 28.0% (+12.6 п.п.).
2. **Даже kNN с 20× большей памятью (35.7 MB) не догоняет таблицу**:
   14.68 vs 13.74 PPL. Агрегация счётчиков строго выигрывает у сырого retrieval.
3. Почему: kNN-датастор хранит дублирующиеся (контекст→следующий) пары, а таблица
   их суммирует в оценку MLE — при фиксированном бюджете агрегация эффективнее.
4. Вывод для morin-filter: выбор β-корпусного приора (Jelinek-Mercer) вместо
   kNN-LM **оправдан**: тот же выигрыш при меньшей памяти.

## Conclusion

**Подтверждено**: β-приор — правильный селектор. kNN-LM при равной памяти
проигрывает в 1.84×, при 20× памяти лишь догоняет.
